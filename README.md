# 纸牌会客厅 · Godot 3D 卡牌模板与本地人机玩法

本仓库包含可复用的 3D 卡牌模板、UNO 风格「彩序」与独立「21 点」。所有牌面为原创图形，无真实货币、充值、支付或兑换。Godot **4.7.2** 导入 `project.godot` 后按 F5，进入玩法大厅，三个入口均可直接运行。

## 21 点：八人环桌对中央庄家

大厅「21 点」或 `scenes/blackjack_game.tscn`：保留真实3D八角桌、固定八席身份、中央庄家、同实体飞牌与多视角。1–8位本地真人共用设备轮流手动操作；无玩家AI、无联网。

- 「设置全桌下注」一次列出八席，金额默认0；可明确点击「全部填100（按余额）」再确认。0自愿跳过，非零必须整十且不超余额。人数控件限制使用前1–8席，八席模型位置不变。全0拒绝开始；不会自动补金币。每席初始1000虚拟金币。
- 美式发牌：每人两张全明，庄家一明一暗；仅庄家暗牌与牌堆脱敏，不含牌面、点数、花色或标题，不可点击偷看。玩家无暗牌peek。
- 天然Blackjack优先独立结算，净赔率2:1：下注100返300（含本金），双方天然也玩家胜。随后庄家天然预检，未天然的玩家立即输。已支付天然不再参与末结算。
- 普通赢净1:1；平局退本金。玩家五张未爆自动锁手，等待庄家结果：胜普通庄家，双方五张未爆平局；庄家五张未爆胜普通玩家。爆牌优先判负。三张以上21为普通21。
- H要牌、S停牌、D加倍：仅未行动初始两张，追加同额，补一张强制停牌。按钮、余额与状态标明当前玩家，行动切换对应座位相机，不交换模型身份。V第一/第三视角、T俯视、右键转头、R复位、Tab自由看桌。
- 六副牌共312张，每张唯一物理ID。局中不回收；两局间回收洗牌。异常耗尽只退款尚未结算的下注，已即时支付天然保留，避免重复付/撤回既结算结果。
- 返回大厅保留整桌牌局、下注和钱包，重入继续；菜单暂停庄家和飞牌。重置需确认，将八席余额替换为1000。关闭程序结束会话，无存档，无真实现金价值。不含分牌、保险、投降。

### 庄家概率最优策略

庄家不受S17约束，可自由要牌或停牌。目标是对所有尚未结算玩家最大化期望金币净收益，而非赢最多人数。读取全部手牌和下注，只用剩余牌的A、2…9、10值张数，不读取未来顺序。

`blackjack_dealer_solver.gd` 使用有限无放回计数动态规划比较停牌收益与要牌后的最优期望值；递归至爆牌或五张锁定，期望相同则停牌。每抽一张后重算。下注权重、软A、五张优先、双方五张平局均纳入。结果是当前规则与已知牌组成下的概率最优决策，不保证单局盈利。

### 结构与回归

- `blackjack_ring_rules.gd`：八席同步模型、显式下注数组、守恒/版本校验、原子加倍、优先支付与幂等结算。
- `blackjack_dealer_solver.gd`：纯概率庄家策略；`ring_card_table.gd`：复用八角桌模型中立呈现器；`blackjack_game.gd`：本地真人控制和UI。
- `card_session.gd` 保存内存会话。旧 `blackjack_rules.gd` / `blackjack_legacy_game.gd` / legacy场景保留原规则和原测试，仅用于回归。UNO与模板入口保持不变。

### 可重复验收

运行 `Godot_v4.7.2-stable_linux.x86_64 --path . res://scenes/blackjack_game.tscn -- --blackjack-fixture=both-natural`，设置八席各100并确认：1号天然与庄家天然同时出现，1号返300，余额1200；其他普通玩家各输100。

`five`：1号2+3，连续手动要三张2成为五张，锁手等待庄家；`five-tie`提供小牌庄家继续至五张的演示牌序。`double`：1号5+6，下一张10，加倍变21；其他七席必须手动操作，等待多久都不会自动代玩。`natural`、`dealer-natural`、`bust`、`soft17`另有确定开局。默认牌序按八位参与者准备；名称加`-2`（例如`both-natural-2`、`double-2`、`five-tie-2`）即按两位参与者准备，下注弹窗人数也默认为2。实际下注人数须匹配fixture；其他人数用正常随机模式。fixture仅重排真实ID，不在重进大厅时注入。

## 彩序 / UNO 风格玩法

大厅选择「彩序」，或运行 `scenes/uno_game.tscn`，默认你对战三个机器人；Esc 可选择 2–8 人、初始手牌张数和四项额外规则后重新开始。额外规则默认全部关闭；修改勾选后只有「重新开始」才生效，「继续游戏」保留本局规则；下一局沿用人数、初始手牌与规则配置。

- 点击亮边手牌出牌；D /「摸一张」摸牌，随后可以打刚摸到的牌或保留结束回合
- 万能牌先选颜色，取消不消耗卡牌；+4 允许虚张声势，受罚者可以质疑
- 剩两张时可勾选「随本次出牌喊 UNO」；漏喊后、下一位实际行动前仍可补喊或被抓
- 机器人行动前有可见停顿，留出喊 UNO / 抓漏喊的时间；机器人并不总会记得喊
- V 第一 / 第三人称，T 俯视，右键转头，R 复位，Tab 收起真实 3D 手牌
- Esc 暂停并查看规则、人数设置或切回独立模板演示
- 每局按各玩家剩余手牌分由低到高排名，同分并列；不累计胜者分、不设500分比赛

这是同机单人对机器人原型，不含联网、账号、存档、热加入、商业级 AI 或声音。人数固定为 2–8，是官方 2–10 人范围的一个子集。

## 规则基线与明确约定

基于 Mattel 的 [classic UNO Basic](https://service.mattel.com/instruction_sheets/UNO%20Basic%20IS.pdf) 和 [53641 规则](https://service.mattel.com/instruction_sheets/53641.pdf)：108 张、默认每人七张（可配置）、同色 / 数字 / 符号匹配、一次只打一张、不叠加 +2 / +4、不抢出、不使用 7–0。两人 Reverse 等同 Skip。可主动摸牌，但摸后只可打刚摸到的那张。弃牌回收保留顶牌与当前颜色。

+4 的合法性按出牌前当前颜色检查，不因同数字 / 功能而非法。只有受罚者可质疑：成功则出牌者摸四，质疑者正常行动；失败则质疑者摸六并跳过；接受则摸四并跳过。质疑后保持出牌者选定颜色，是经典规则对后续顺序未详述处的明确实现约定。最后一张 +2 / +4 的罚牌和质疑先处理，再结算。

每局随机洗牌，轮流发完指定手牌后直接从剩余牌堆翻一张起始牌。始终由1号开始，按玩家编号往后行动。起始 Skip / Reverse / +2 / +4 均不触发功能，不重抽、不抢牌、不产生叠加债务；起始 Wild 或 +4 由1号先选择有效颜色，再进行1号的正常回合。后续打出的功能牌照常生效。

初始手牌默认7，范围为1至 floor(107 / 人数)：2/3/4/5/6/7/8人分别最多53/35/26/21/17/15/13张，始终留出起始牌。菜单更改人数会同步上限并限制数值；继续游戏不应用未提交设置。初始仅1张万能牌且开启禁最后万能时，不擅自补发，玩家必须正常摸牌。只剩顶牌且所有玩家都无法出牌/摸牌时，以全员连续空摸后过牌结束，仍按剩牌分排名。

数字按面值（0–9），彩色功能牌10，换色万能牌20，+4万能牌40。结算每位玩家自己的剩牌分，分数越高排名越低；同分共用名次（例如1、1、3），不以座位、剩牌张数或先出完顺序破同分，零分手牌也可与空手玩家并列。全部罚牌和质疑结算后才确定排名。旧的胜者累计500分模式已移除，下一局独立计分。UNO 漏喊窗口在下一位实际摸牌 / 出牌时关闭；程序分配轮次不会提前关闭它。AI 的 +4 质疑选择只使用公开状态，不查看对手秘密牌。

## 可选房规与组合约定

四项开关独立设置，均默认关闭；无论是否开启，都使用上述自定义起牌与剩牌计分。

1. **持续抽牌**：当前没有可出牌时，持续摸至第一张可出牌并立即打出。彩色牌自动打出；万能牌必须选择颜色，不能取消或保留。若原手牌已有可出牌而主动摸牌，仍按普通摸一张处理。牌堆和可回收弃牌耗尽就停止，允许结束回合，不会无限循环。
2. **抢牌**：可用与最新顶牌**颜色和数字 / 功能完全相同**的彩色牌抢出，包括自己连续抢出；万能牌及 +4 不可抢。抢牌替代上一张尚未结算的功能效果，已打出的牌仍留在弃牌堆。反转不会重复翻转、跳过不会重复跳人，+2 只替代当前这一张贡献，叠加链更早的债务保留。
   - 窗口持续到下一位实际出牌 / 摸牌请求先被接受，没有固定倒计时或额外「继续」步骤。下一位也与抢牌者比请求到达顺序。无效请求不关闭窗口。轮到自己时默认点击为正常出牌（同色 +2 可叠加）；要替代上一张效果，先勾选「本次抢牌」。轮次外的完全相同牌直接点击抢出。该勾选在状态变化后自动重置。
   - 本地规则实例承担房主权威：请求串行验证，带状态版本可拒绝过期请求；没有新增真实联网功能。机器人有独立反应延迟，也可能先完成正常出牌 / 摸牌；暂停和动画期间共同暂停输入。
   - 界面先预览下一位与方向，实际下一次合法行动确认上张效果；待罚 +2 的玩家可按 D 或「摸罚牌并跳过」，这就是实际摸牌。普通数字 / 跳过 / 反转使手牌清空时直接结束并结算排名，因为抢牌不会把已出的牌退回手中；最后的罚牌先结算再计分。
3. **+2 叠加**：累计 +2 可再接任意颜色 +2 或 +4；出现 +4 后只能再接 +4。不能继续叠加的玩家摸全部累计罚牌并跳过，罚摸本身不触发持续抽牌。开启此房规时 +4 不进行质疑；关闭时保留经典 +4 质疑。连锁期间有玩家先后出完手牌时，罚牌结束后若仍有人空手则结束本局；最早出完且仍为空手者记录为触发结束者，最终名次只按剩牌分（多位空手同为0分并列）。若罚牌绕回先出完者，其摸牌后不再是空手候选。
4. **禁止最后一张万能牌**：出牌后只剩一张 Wild 或 +4 时，强制摸一张；该次转换只罚摸一次，即使新摸到的也是万能牌也不循环。抢牌链结束时处理，避免自己的连续抢出触发中间重复罚摸。可抽牌耗尽时如实报告，绝不凭空造牌，最后一张万能牌仍禁止打出；若全员均无法出牌或摸牌，以有限的空摸 / 过牌检测结束并按剩牌分排名。

UNO 宣告、剩牌计分、回收、视角和对手手牌隐私在房规模式中沿用；设置与状态机只在 UNO 层，通用 3D 模板不依赖这些房规。

## 分层与从玩法反馈到模板

- `scripts/card_3d.gd` + `scenes/card_3d.tscn`：原可编辑 3D 卡牌，双面/隐藏/悬停/同一节点动画
- `scripts/table_demo.gd` + `scenes/table_demo.tscn`：原自由操作模板，单独 F6 运行，原行为与 1211 项基线断言保留
- `scripts/rules_table.gd`：新通用规则宿主，仅负责呈现任意规则模型快照。稳定卡牌 ID、任意手牌数量、自适应布局、单顶牌弃牌堆、隐藏牌堆节点、真实同节点飞行、固定玩家权限、请求信号与独立交互/模态锁；没有 UNO 依赖
- `scripts/uno_rules.gd`：独立同步规则与回合状态，不依赖场景或 UI，可用固定随机种子测试
- `scripts/uno_game.gd` + `scenes/uno_game.tscn`：规则与模板的适配、人机控制、颜色 / 质疑 / 暂停 / 结算 UI
- `assets/uno/`：54 种原创卡面及牌背；`tools/generate_uno_art.py` 可用 Pillow 重建，运行游戏无需 Python

通用宿主核心 API：`apply_state(player_ids, hands, deck_cards, discard_cards, texture_provider, animated)` 原子校验快照、同步稳定 ID 的原卡节点；`card_requested(id)` / `draw_requested` 只报告意图，由外部规则决定合法性。`set_interaction_blocked()` 仅锁规则操作，不禁用相机；`menu_open` 独立锁模态输入。`card_node(id)` / `player_hand(index)` / `discard_count()` 供宿主查询。牌堆数组最后一张为顶牌。卡牌视觉隐藏仅是本地表现，不是联机保密协议。

## 原模板使用说明

# ARC · 通用 3D 卡牌

独立的 Godot **4.7.2** 工程。真实 3D 圆角薄片卡牌、双面纹理、正八角透视桌面与八座位同世界浮空手牌，可作为自己的卡牌玩法的基础；没有绑定战斗、费用或 TCG 规则。

## 运行

使用 Godot 4.7.2 导入 `project.godot`，打开 `scenes/table_demo.tscn` 后按 F6 运行模板演示；F5 默认进入玩法大厅。

- 悬停：单张手牌向上弹出、放大并完整显示；离开后落回底边，其他手牌保持靠下
- 左键：选中；Ctrl / Command + 点击增减多选；Enter 或「出牌」将所选手牌作为一组打出
- 普通拖拽只移动单张：移动超过 8 像素开始；多张选择通过按钮 / Enter 成组出牌
- 桌面框内：放入桌面；拖回悬浮手牌所在区域：收回并重新排布
- 手牌悬浮在玩家眼前的真实 3D 空间，跟随玩家转头；与桌面共享同一个世界
- 框外、区域间隙、区域已满：归回原区域，不会丢失卡牌
- 右键按住拖动 / 方向键：原地转头（第一人称）或环绕观察（第三人称）
- V / 视角按钮：切换第一 / 第三人称；T：独立正俯视桌面；R：视角复位
- Tab / 收起手牌：原 3D 手牌缩到视线右下方，直接移动鼠标自由转头；再次 Tab 展开并恢复鼠标选牌
- 不操作手牌 1.3 秒后会自动轻微缩小 2%；移入下方手牌区、悬停、选中或拖拽时恢复；不等于手动收起
- 桌面牌悬停 0.45 秒：查看单张或同次出牌组的放大预览，隐藏 / 无信息仍为问号，背面仍为牌背
- F：翻转选中的牌；H：独立切换隐藏正面（问号）；D 或点击牌堆：摸一张，沿弧线从牌堆飞入当前玩家手牌
- 1–8 / Esc 菜单内 1–8 号座：切换已入座玩家，空位不可选；独立手牌与视角；只操作当前座位或共享桌面牌
- Esc：打开 / 关闭调试菜单；打开时释放鼠标、安全取消拖拽并清空选择
- 右上「最近出牌」保留最近一次完成的出牌（单张或一组），标明玩家 / 座位；收回或再翻牌不会改变该次快照
- 牌堆为最多 12 层真实 3D 牌背，带剩余张数；摸牌和出牌使用原卡节点，不复制逻辑卡牌
- 下局人数：选择 2–8 人后点「开始新局」，开局均匀分配座位并固定到本局结束；仅修改人数不影响当前局
- 重置本局：保留本局玩家与座位，恢复 64 张牌；首位玩家 5 张，其余玩家各 3 张；默认 8 人局牌堆剩 38 张
- P1 的第二张是隐藏牌，第四张没有卡面信息，均显示问号；第二张取消隐藏可恢复原图，第四张仍为问号
- F11：第一人称固定展示构图；再按 V 可展示真实牌背
- F12：截图保存到 `captures/cards_first_XX.png` / `captures/cards_third_XX.png`；菜单中仍可截图，保存为 `captures/cards_menu_XX.png`

演示限制：8 个独立座位，每席最多 8 张手牌，共享桌面最多 16 张牌，桌面为正八角形，对边距离 24 世界单位（边心距 12；对角顶点距离约 25.98）。牌堆为空时禁用抽牌。本版是同机切换座位的本地原型，未实现联机、房间或网络授权。

## 组件 API

卡牌平放于 **XZ 平面**，正面朝 +Y。根节点拥有布局位置和朝向，子节点 Visual 单独处理翻转与悬停，避免动画互相覆盖。`configure` 可在实例加入场景之前或之后调用。

```gdscript
var card = preload("res://scenes/card_3d.tscn").instantiate()
card.configure({
    "id": "my-card-001",
    "title": "自定义名称",
    "face": preload("res://assets/card_0.svg"),
    "back": preload("res://assets/back.svg"),
    "size": Vector2(1.65, 2.32),
    "thickness": 0.045,

    "custom_value": 42, # 自定义字段原样保留在 card.data
})
```

可调导出属性包括尺寸、厚度、圆角半径、正反面纹理、初始朝向和悬停缩放。

### 隐藏与无信息正面

`face_hidden` / `set_face_hidden(bool)` 只控制正面材质。隐藏时翻到正面仍为 `?`，翻到背面仍使用原牌背；取消隐藏恢复原卡面。未提供 face 纹理时自动使用同一个问号正面，包括新建空组件及 `configure({})` 替换掉旧卡信息后。`configure` 将缺失的 face 视为无信息，不保留旧卡面。

`public_description()` 在隐藏或无卡面时返回“未知卡牌”，背面时返回“牌背”，已公开正面才返回标题。选中、抽牌、翻面状态文字均走这个接口；悬停不显示原始标题。`public_snapshot()` 仅返回公开展示白名单，不暴露 id、data 或纹理资源；隐藏、无卡面或背面时没有 title 字段。

重要：视觉隐藏不是安全边界。原始数据仍保留在本地 `card.data`，本版切座位也只是调试/本地演示。后续联机需要服务端按玩家权限发送脱敏数据，对方未知牌只发送占位数据；不能把秘密下发后靠问号、防点击或客户端布尔值防窥。`public_snapshot()` 是展示输出接口，不是完整的网络授权协议。

### 信号

- `face_visibility_changed(card, hidden)`：正面隐藏状态改变
- `flipped(card, face_up)`：发起翻面时触发
- `selection_changed(card, selected)`：选择状态实际改变时触发
- `drag_started(card)`：拖拽开始，一次生命周期仅触发一次
- `drag_finished(card, accepted)`：落点判定完成；取消为 false
- `zone_changed(card, old_zone, new_zone)`：成功切换所属区域

组件不擅自管理全局鼠标和区域规则。宿主调用 `begin_drag()` / `end_drag(accepted)`，并在接受移动时调用 `set_zone()`。演示的 `move_card` 统一校验容量、变更数组和区域、重新布局；`screen_drop_zone` 先判定屏幕手牌区，再用 `drop_zone` 判定射线与桌面交点的有效区域。替换这些方法即可接入其他游戏。

### 同世界浮空手牌与视角

桌面、牌堆和手牌只有一个 `World3D`，不使用 `SubViewport` 或 HUD 贴图。每席自己的 `PlayerLookRig1…8` 固定在对应玩家位置，包含透视相机和 `FloatingHand1…8` 节点。手牌使用原有 `Card3D`，位于相机前方 4.6 个世界单位、竖向中心贴齐视口底边，静止时下半张在画面之外，卡面正对玩家；卡牌整体缩放为 0.68，悬停、翻转仍由原组件处理。

第一人称右键拖动调整 yaw / pitch，pitch 限制在 −75° 到 +65°，玩家位置不变。`ObserverCamera` 为独立第三人称观察相机，初始俯瞰八人牌桌，从 P1 对面看到同一张 P1 手牌真实的背面。其他玩家的牌面朝各自拥有者；当前查看者不是牌主时，真实正面材质也替换为牌背，避免俯视 / 第三人称绕看泄露对手手牌。这不改变 face_hidden、face_up 或原始 data；切到牌主后恢复其允许看到的正面。切换视角不会翻面、复制或重新挂接手牌；第三人称右键只环绕观察者，不会改变玩家手牌朝向。

`card_screen` 与 `pick` 统一通过当前相机投影 / 射线拾取。`hand_rect` 将浮空手牌的真实边界投影为收回目标；`screen_drop_zone` 首先排除顶部和实际按钮区，再判断手牌与桌面。拖拽时原卡节点临时置于世界根节点、沿当前相机前方的 3D 平面移动；落点成功后重新挂到所属区域。切换 / 复位视角和调整窗口尺寸会安全取消拖拽，恢复原区域。

### 正八角桌几何

桌面为实际闭合的八棱柱网格，外缘、内层桌布与八边嵌线保持同心正八角形；不是矩形桌面上的八角贴图。八条边等长，相邻边中心方向相差 45°。P1 位于 +Z，P2 位于 +X/+Z，其后按相同方向每隔 45°编号到 P8。

每席固定玩家位置在距中心 11 个单位的圆上、对应边中垂线上，高度 8；默认俯角 38° 朝向桌心。地面座位标记同步按对应边旋转，浮空手牌仍跟随该席原有玩家视线。中央 16.4×8.4 出牌区域和左上方牌堆均保留并完全位于八角桌内。第三人称默认全景完整容纳八角外轮廓。

### 开局固定座位（2–8 人）

物理座位始终为顺时针 1–8 号，不因人数变化重新编号。开局按输入玩家 ID 顺序，将第 i 位玩家（i 从 0 开始）分到 `1 + floor(8*i/N + 0.5)` 号座：

- 2 人：1、5
- 3 人：1、4、6
- 4 人：1、3、5、7
- 5 人：1、3、4、6、7
- 6 人：1、2、4、5、6、8
- 7 人：1、2、3、4、6、7、8
- 8 人：1–8

相邻玩家的循环座位间隔最大只差 1。未入座位置显示「空位」，不发牌，不可切换或接收转移。当前玩家身份和物理座号分别显示。只有「开始新局」提交人数修改；「重置本局」、切视角、抽牌和出牌都保留当前映射。无中途加入、离开或动态调位。

```gdscript
start_round(["alice", "bob", "carol"]) # true；分别分到 1、4、6 号座
seat_for_player("bob") # 4；查无玩家返回 0
player_at_seat(4) # "bob"；空位 / 非法座号返回空字符串
round_mapping() # 映射副本，修改返回值不影响本局
set_pending_player_count(5) # 仅修改下局设置
start_pending_round() # 用稳定演示 ID 玩家1…玩家5 开始新局
```

`start_round` 只接受 2–8 个唯一且非空白的 String / StringName ID，失败返回 false 且不改变当前局。输入数组会复制，玩家 ID 与物理座位分开保存。开始新局会取消拖拽、清除选中、清空桌面并重新发牌。

### 八座位宿主 API

- `seats`：8 个座位字典，包含物理 seat_id（1…8）、player_id（空位为空字符串）、兼容物理 id（P1…P8）、rig、camera、anchor、hand、默认 yaw
- `set_active_seat(index)`：0–7（仅已入座）；取消拖拽、清空选择并切换活跃相机与手牌，返回是否有效
- `hand`、`hand_world`、`player_rig`、`first_camera`：指向当前座位，保留原宿主接口
- `transfer_to_seat(card, index)`：宿主级本地转移接口，校验来源与容量，取消拖拽，保留同一节点、卡面隐藏及翻转状态；不是远程玩家操作授权
- `total_cards()`：8 席手牌 + 桌面 + 牌堆的总数，不计算牌堆视觉替身
- `move_card(card, zone)`：只接受当前玩家手牌和共享桌面中的卡牌；其他席牌只能由各席激活后操作，或宿主显式转移

各席独立布局与世界朝向，不会因当前座位改变而重建卡牌。切换当前玩家不冒充联机身份认证。

### 摸牌、出牌与最近一组

摸牌时立即从牌堆扣除、为当前席手牌预留容量，原卡从牌堆顶沿世界空间弧线飞入手牌并翻开。出牌时同一节点沿弧线、轻微倾斜后落到共享桌面。动画中的目标始终按真实手牌锚点计算，转头时仍追随对应玩家。可连续摸牌；手牌满、牌堆空或出牌组超出桌面容量时整次操作拒绝，不丢失牌、不覆盖历史。

`play_cards(Array[Card3D])` 原子提交当前席的一组手牌；`play_selected()` 提交多选；`select(card, true)` 增减选择。桌面卡、其他席手牌、重复卡或超容量混入组时整体返回 false。拖拽仍为单张操作，Ctrl / Command 点击只选择、不触发拖拽。

`flights` 仅跟踪展示动画，卡牌立即归属最终区域，因此总量和容量不受动画时长影响。飞行中的牌暂不参与鼠标拾取。切座位、切 / 复位视角、调整窗口尺寸时完成已提交动画，随后处理拖拽取消；重置和新局直接清空动画和历史，不留下延迟回调。`advance_flights(delta)` 驱动动画；`settle_flights()` 可让宿主立即完成已提交飞行。

`last_play_snapshot()` 返回最近一次完成出牌的深拷贝，含 `actor`（玩家 ID）、`seat`（1–8 号座）和 `cards`（每张的 public_snapshot）。快照不引用原卡、不含私有 data / id / 纹理；隐藏、无信息正面为问号，背面保留牌背，不显示名称。快照按该次打出时的公开状态保留，之后收回、翻转、显示牌面不会回写这次历史；重置 / 新局清空。预览只从已公开白名单生成，不读取旧卡的私有属性。

### 区域与生命周期

演示使用 `hand`、`play`、`deck` 三个区域名。拖拽不提前更改数组或所属区域，只有合法落点才提交；无效落点、Esc、重置均安全结束拖拽。松开鼠标即使位于 HUD 上也会完成判定，不会卡在拖拽状态。每次抽牌与移动都更新牌堆显示和计数。
